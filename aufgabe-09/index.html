Torustextur

Einsendeaufgabe 09

01

Texturen auf einer Modelloberfläche

In dieser Szene wird ein parametrisch erzeugter Torus mit zweidimensionalen Texturkoordinaten versehen. Die beiden Parameterrichtungen des Modells werden dabei auf den Bereich von 0 bis 1 abgebildet und ermöglichen eine vollständige Texturierung der gekrümmten Oberfläche.

Als Bildtextur wird eine speziell für diese Aufgabe erzeugte quadratische Textur mit einer Auflösung von 1024 × 1024 Pixeln verwendet. Sie wird in JavaScript geladen, als WebGL-Textur angelegt und über Texture Unit 0 an den Fragment-Shader übergeben.

Als Erweiterung wurde zusätzlich eine prozedurale Textur implementiert. Das Muster entsteht vollständig im Fragment-Shader aus periodischen Sinus- und Kosinusfunktionen und wird langsam über einen Zeitparameter animiert.

Zur Untersuchung der Oberfläche können die Kamera bewegt, eine automatische Kamerafahrt gestartet und die Lichtquelle schrittweise auf einer Kreisbahn um den Torus versetzt werden. Zwischen Bildtextur und prozeduraler Textur kann jederzeit umgeschaltet werden.

04

Texturkoordinaten

Parametrischer Torus

Der Torus wird aus zwei Parameterrichtungen erzeugt. Eine Richtung läuft um den gesamten Torus, die zweite Richtung umläuft den Querschnitt des Torusrohrs.

Diese beiden Richtungen eignen sich direkt für die Berechnung der zweidimensionalen Texturkoordinaten.

UV-Mapping

Für jeden erzeugten Vertex werden zwei zusätzliche Werte zwischen 0 und 1 gespeichert.

s = i / majorSegments

t = j / minorSegments

Damit wird die vollständige Textur einmal um beide parametrischen Richtungen des Torus gelegt.

Texture-VBO

Die Texturkoordinaten werden entsprechend der Lerneinheit TXR in einem eigenen Vertex Buffer Object gespeichert.

model.vboTextureCoord

Beim Zeichnen wird dieser Buffer mit dem Shader- Attribut aTextureCoord verbunden.

Übergabe an den Fragment-Shader

Der Vertex-Shader übernimmt die Texturkoordinaten über aTextureCoord und gibt sie als vTextureCoord an den Fragment-Shader weiter.

vTextureCoord = aTextureCoord

05

Bildtextur

Laden der Bilddatei

Die Bildtextur wird mit einem JavaScript- Image-Objekt geladen. Nach erfolgreichem Laden werden die Bilddaten an ein WebGL-Texture-Objekt übertragen.

gl.createTexture()

gl.texImage2D(...)

Texture Unit

Beim Rendern wird die geladene Bildtextur an TEXTURE0 gebunden und über den sampler2D des Fragment-Shaders gelesen.

gl.activeTexture(gl.TEXTURE0)

uniform sampler2D uTexture

Fragmentfarbe

Im Bildtextur-Modus wird die Fragmentfarbe anhand der interpolierten Texturkoordinaten aus der Bildtextur gelesen.

texture2D(uTexture, vTextureCoord)

Gestaltung der Bildtextur

Für diese Aufgabe wurde eine eigene KI-generierte Ausgangstextur im Stil von türkisfarbenem und dunkelblauem Marmor beziehungsweise poliertem Mineralgestein erstellt. Dabei wurden helle Adern, dunkle Bereiche und unterschiedliche Türkistöne verwendet, damit die Verteilung der Textur auf der gekrümmten Torusoberfläche deutlich erkennbar bleibt.

Die Ausgangsgrafik wurde anschließend für die Verwendung in WebGL auf eine quadratische Auflösung von 1024 × 1024 Pixeln angepasst und als torus-texture.png gespeichert. Es wurde keine fremde Bilddatei direkt als fertige Textur übernommen.

Die Textur wurde speziell für diese Einsendeaufgabe mit der Bildgenerierung von ChatGPT erstellt und anschließend für die Verwendung im Projekt angepasst.

06

Erweiterung: prozedurale Textur

Ohne zusätzliche Bilddatei

Die prozedurale Textur wird vollständig im Fragment-Shader berechnet und benötigt keine zusätzliche Bilddatei.

Grundlage sind dieselben interpolierten Texturkoordinaten vTextureCoord, die auch für die Bildtextur verwendet werden.

Periodisches Muster

Die Texturkoordinaten werden zunächst auf einen Winkelbereich von 0 bis 2π abgebildet. Anschließend werden mehrere periodische Sinus- und Kosinusfunktionen miteinander kombiniert.

Durch ganzzahlige Frequenzen besitzen Anfang und Ende der Textur dieselben Funktionswerte. Dadurch kann das Muster ohne harte sichtbare Naht um den geschlossenen Torus laufen.

Animation und Farbgebung

Ein Zeitwert wird als Uniform an den Fragment-Shader übergeben und verändert langsam die Phasen mehrerer Wellenfunktionen. Dadurch entsteht eine ruhige, fließende Bewegung des prozeduralen Musters.

Die berechneten Werte mischen dunkle Petroltöne, Türkis und helle Minttöne. Zusätzliche schmale Strukturen erzeugen den Eindruck feiner mineralischer beziehungsweise marmorartiger Adern.

Direkter Vergleich

Über die sichtbaren Schaltflächen kann jederzeit zwischen der geladenen Bildtextur und der prozedural berechneten Oberfläche gewechselt werden.

Die Bildtextur bleibt statisch, während die prozedurale Variante animiert ist. Beide Varianten verwenden jedoch dieselben UV-Koordinaten des Torus.

07

Kamera und Beleuchtung

Manuelle Kamerasteuerung

Mit den Pfeiltasten kann die Kamera horizontal um den Torus bewegt und ihr vertikaler Blickwinkel verändert werden.

Dadurch kann die Textur auf Außen-, Innen- und Rückseite des gekrümmten Modells aus unterschiedlichen Perspektiven untersucht werden.

Automatische Kamerafahrt

Zusätzlich steht eine automatische Kamerafahrt auf einer Kreisbahn um den Torus zur Verfügung.

Sie wird über die Taste K oder über die entsprechende Schaltfläche gestartet und pausiert. Die manuelle Kamerasteuerung bleibt weiterhin verfügbar.

Draufsicht und Fokus

Über die Taste O oder die Schaltfläche „Draufsicht“ kann auf eine hohe Kameraperspektive gewechselt werden.

Unabhängig von der gewählten Perspektive bleibt die Kamera auf den Mittelpunkt des Torus ausgerichtet, sodass das texturierte Modell im Zentrum der Darstellung bleibt.

Bewegliche Lichtquelle

Die Szene verwendet eine Punktlichtquelle, deren Position schrittweise auf einer Kreisbahn um den Torus bewegt werden kann.

Mit der Taste L oder der Schaltfläche „Licht weiterschalten“ wird die Lichtposition jeweils um 15 Grad verändert. Dadurch lassen sich diffuse Beleuchtung und Glanzlichter aus verschiedenen Richtungen betrachten, ohne die Texturkoordinaten zu verändern.

08

Dokumentation

Ausgangspunkt

Die Implementierung der Bildtextur orientiert sich an der Lerneinheit TXR.

Verwendet wurden insbesondere der dort beschriebene Ablauf zum Laden einer Bilddatei über Image und initTexture(), das eigene Texture-VBO sowie die Übergabe der Textur über sampler2D und Texture Unit 0.

Umgesetzte Erweiterungen

Als bewertete Erweiterung wurde eine prozedurale Textur umgesetzt, die vollständig im Fragment-Shader erzeugt und über die Benutzeroberfläche mit der Bildtextur verglichen werden kann.

Zusätzlich wurden eine langsame Animation des prozeduralen Musters, eine optionale automatische Kamerafahrt, eine Draufsicht und eine schrittweise bewegliche Lichtquelle ergänzt.

Test und Qualitätssicherung

Die Anwendung wurde in Google Chrome unter macOS getestet. Geprüft wurden das Laden der 1024 × 1024 Pixel großen Bildtextur, die vollständige Texturabbildung auf dem Torus sowie der Wechsel zwischen Bildtextur und prozeduraler Textur.

Zusätzlich wurden die manuelle Kamerasteuerung, die automatische Kamerafahrt, die Draufsicht, die Animation der prozeduralen Textur und die schrittweise Bewegung der Lichtquelle getestet.

Die Anwendung wurde über einen Webserver beziehungsweise GitHub Pages ausgeführt. Abschließend wurde die Browserkonsole auf JavaScript-, Shader-, WebGL- und Ladefehler kontrolliert.

Quellen und verwendete Hilfsmittel

  • Lerneinheit TXR: Laden und Verwenden von Bildtexturen in WebGL.
  • Lerneinheit TXR: Texturkoordinaten und model.vboTextureCoord.
  • Lerneinheit TXR: sampler2D, texture2D() und Texture Unit 0.
  • glMatrix 2.2.0 aus dem bereitgestellten Lehrmaterial: Matrix- und Vektoroperationen.
  • Bildtextur: speziell für diese Einsendeaufgabe mit der Bildgenerierung von ChatGPT erzeugt und anschließend auf 1024 × 1024 Pixel für die WebGL-Verwendung angepasst.
